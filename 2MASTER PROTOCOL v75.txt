РАЗДЕЛ III. ЗАЩИТА КОМПИЛЯТОРА, ТИПОВ И БАЙТКОДА JVM

[C-01] Защита от коллизий сигнатур JVM (JVM Signature Clash Guard)

В Kotlin типы String и String? компилируются в один дескриптор
Ljava/lang/String;. Запрещены перегрузки методов, различающиеся только признаком
nullable одного ссылочного типа. Объявляется ровно одна каноническая функция
(text: String?, ...).

[C-02] Защита от дублирования JVM-классов (Duplicate JVM Class Guard)

Вспомогательные структуры данных (data class Quad, Tuple4) не могут объявляться
повторно внутри одного класса. Дубликаты удаляются, оставляется 1 каноническое
объявление.

[C-03] Защита от каскадного обвала типов (Anti-Cascading Inference Shield)

Запрет цепочек .let над непроверенными объектами:

view?.findViewById<View>(resId)?.let { v -> v.context... } // ЗАПРЕЩЕНО

Использовать плоские проверки на null:

val target = view?.findViewById<View>(resId)
if (target != null) { target.background = ... } // ПРАВИЛЬНО

[C-06] Иммунитет к сбросу типов (Smart Cast Immunity & Mutable Shadowing)

Запрет Smart Cast для var: В Kotlin компилятор запрещает автоматическое
приведение типов для изменяемых свойств. Любые проверки на null или приведение
типов (например, is ViewGroup) изменяемого свойства обязаны предваряться
созданием локальной неизменяемой val копии:

val safeRoot = panelContainer as? ViewGroup ?: return // ИММУНИТЕТ

РАЗДЕЛ IV. БЕЗОПАСНОСТЬ РАНТАЙМА И КИНЕМАТИКА

[R-01] Задержка аппаратного композитинга (Two-Frame VSYNC Flush Barrier)

Любой захват кадра через MediaProjection обязан выдерживать временной барьер не
менее 50 мс (сброс 2-3 кадров SurfaceFlinger) после сокрытия оверлеев (alpha
= 0f), гарантируя абсолютно чистый кадр без визуального шума приложения.

[R-02] Протокол чистой записи шаблонов и защита от двойных кликов

1.  Разделение режимов: Простая запись фиксирует координаты без MediaProjection.
    Умная запись создает строго один шаблон.
2.  Дедупликация (Debounce Guard): Внедряется барьер подавления повторных
    касаний на 400 мс во избежание паразитных двойных срабатываний ACTION_DOWN +
    ACTION_UP.
3.  Pre-Touch Snapshot: Скриншот снимается до того, как целевая игра отрисует
    эффект нажатия (Ripple). Отрисовка маркеров касания (dotPaint) блокируется

[R-04] Безопасность аппаратных буферов (HardwareBuffer Lifecycle)

Любой захват кадра через ImageReader обязан освобождать нативные ресурсы строго
в блоке finally (image.hardwareBuffer?.close()).

### [U-05] Иммунитет визуальной иерархии (Lifecycle UI Resiliency)
Из-за особенностей жизненного цикла Android (перерисовки, смена тем, updateUiState) программные обновления состояния могут затирать декларативные стили XML. Все критические стили (основные акценты, деструктивные действия) обязаны защищаться рантайм-инжектором, который принудительно восстанавливает дизайн после любых системных сбросов UI. Частные хардкод-переопределения запрещены.

### [C-07] Синхронизация абстракций (Interface Contract Guard)
Любое расширение интерфейсов-колбеков (Listeners) обязывает немедленно реализовывать (`override`) новые методы во всех классах-имплементаторах. При автоматическом патчинге скрипт обязан добавлять недостающие методы с безопасными `no-op` заглушками `try {} catch() {}` для предотвращения сбоев компилятора "does not implement abstract member".

### [D-07] Хирургическое извлечение AST (Surgical AST Extraction Invariant)
Запрещено "слепое" или жесткое усечение текстовых блоков кода (например, отсечение хвоста файла через регулярные выражения `code[:index]` или нежадные квантификаторы `[\s\S]*?}`). Любое удаление функций или классов обязано производиться СТРОГО через алгоритм подсчета глубины баланса скобок, чтобы гарантировать 100% целостность смежных методов.

### [D-08] Кроссплатформенная кодировка подпроцессов (Subprocess Encoding Guard)
При вызове системных утилит (например, Git) через `subprocess.run(text=True)` скрипты обязаны форсировать использование `encoding="utf-8"`. Игнорирование этого правила приводит к фатальным сбоям `UnicodeDecodeError` на машинах с ОС Windows, где по умолчанию используется кодировка cp1251.
