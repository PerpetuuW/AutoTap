1. ОБЩАЯ АРХИТЕКТУРНАЯ ТОПОЛОГИЯ (Clean & Greenfield Architecture)
--------------------------------------------------------------------------------
Кодовая база AutoTap построена по принципам Clean Architecture с жестким разделением слоев:
• domain/: Доменные сущности (MacroAction, ActionType, MacroScenario, MatchCandidate, Point2D),
  интерфейсы движков (IMacroEngine, ISubroutineManager) и шлюзов (IGestureGateway, IVisionGateway).
• infrastructure/:
  - accessibility/: AutoTapAccessibilityService (служба AccessibilityService, аппаратный захват экрана).
  - gesture/: GestureDispatcher (инжекция кликов, свайпов, путей, симультанный passthrough), HumanGestureEngine (траектории Безье).
  - engine/: MacroExecutionEngine (корутинный исполнительный автомат FSM).
  - vision/: TemplateMatchingEngine (3-уровневый каскад L0/L1/Fine), SmartMaskEngine (контурная сегментация), ColorDetector.
  - ocr/: OcrEngine (интеграция ML Kit с ROI-кроппингом), ExpressionEvaluator (синтаксический парсер выражений).
  - overlay/: OverlayWindowManager, ControlPanelOverlay, TargetOverlayManager, TargetOverlayView,
    CalibrationOverlay, CaptureFrameOverlay, RoiSelectorOverlay, EyedropperOverlay,
    GestureRecorderOverlay, JoystickOverlay, ScreenLockOverlay, RunningBadgeOverlay, DebuggerToolbarOverlay.
  - storage/: ScenarioRepositoryImpl, TemplateRepositoryImpl, PackageBackupManager, AppProfileDetector.
• core/: AppLogger (централизованный логгер с CrashCatcher), SafetyGovernor (термальный контроль),
  CoordinateNormalizer (изотропная проекция координат).

2. ПОДСИСТЕМА ЖЕСТОВ И АППАРАТНОЙ ИНЖЕКЦИИ (Gesture Subsystem)
--------------------------------------------------------------------------------
[2.1] Чистый точечный жест (Zero-Displacement Tap Invariant):
- Проблема: Искусственное смещение (moveTo(x, y) -> lineTo(x + 0.5f, y + 0.5f)) воспринимается игровыми движками
  как микро-свайп, приводя к отмене клика (ACTION_CANCEL) или срыву нажатия кнопки.
- Реализация (GestureDispatcher.kt):
  val path = Path().apply {
      moveTo(safeX, safeY)
      lineTo(safeX, safeY)
  }
  val stroke = GestureDescription.StrokeDescription(path, 0L, durationMs.coerceAtLeast(10L))
  Координата начала и конца строго идентична. Path не является пустым для Android SDK, а операционная система
  генерирует точечный ACTION_DOWN -> ACTION_UP в точке (safeX, safeY) без перемещения.

[2.2] Потоковый FSM-контроллер жестов (TOUCH DOWN -> MOVE -> UP):
- Реализация сквозной ретрансляции жестов при живой записи и управлении стиком:
  1. dispatchSimultaneousTouchDown(x, y):
     Инициализирует жест начальным StrokeDescription(path, 0L, 50L, willContinue = true).
  2. dispatchSimultaneousTouchMove(x, y):
     Использует activeStroke.continueStroke(Path(lastX, lastY -> x, y), 0L, 45L, willContinue = true)
     для непрерывного перемещения пальца без отрыва.
  3. dispatchSimultaneousTouchUp(x, y):
     Завершает жест вызовом activeStroke.continueStroke(Path(lastX, lastY -> x, y), 0L, 20L, willContinue = false).

[2.3] Анатомические свайпы человека (HumanGestureEngine.kt):
- Генерация кривых Безье 3-го порядка с кинематической моделью ускорения-замедления:
  easedT = t^2 * 0.45 при t < 0.35 (разгон), линейный участок при t in 0.35..0.80, квадратичное торможение при t > 0.80.
- Добавление физиологического микро-джиттера (±1.5 px) вдоль перпендикуляра к вектору свайпа.

3. ДВИЖОК КОМПЬЮТЕРНОГО ЗРЕНИЯ И МАСОК (Vision & OCR Pipeline)
--------------------------------------------------------------------------------
[3.1] Трехуровневый каскад сопоставления шаблонов (TemplateMatchingEngine.kt):
- Уровень L0 (Анкерное подтверждение на месте):
  Если шаблон ранее найден в точке (lastX, lastY), проверяется окрестность за 2-4 мс.
- Уровень L1 (Кинематический бокс ±45 px):
  Поиск в ограниченной зоне вероятного смещения объекта с шагом 2 px.
- Уровень L2 (Разреженный пирамидальный скрининг):
  Грубое сканирование экрана с адаптивным шагом (4..8 px) по ключевым пикселям -> выборка топ-8 кластеров
  -> прецизионная проверка -> Non-Maximum Suppression (NMS) для исключения перекрывающихся рамок.

[3.2] Детерминированная гибридная формула оценки схожести:
- hybridScore = colorScore * (1.0f - sobelWeight) + edgeScore * sobelWeight
  где sobelWeight динамически рассчитывается TemplateMorphologyClassifier:
  • Тонкие полосы и микро-иконки (MICRO, THIN_HORIZONTAL, THIN_VERTICAL): sobelWeight = 0.70..0.85
  • Стандартные кнопки (SMALL, MEDIUM): sobelWeight = 0.50..0.70
  • Крупные карточки и фоны (LARGE, HUGE): sobelWeight = 0.30..0.45
  Единая формула гарантирует постоянство порогов сходимости на всех этапах калибровки и выполнения.

[3.3] Анизотропная контурная сегментация (SmartMaskEngine.kt):
- Фильтрация границ с учетом формы исходного поля (Shape-Aware Reach):
  • Прямоугольник: max(|nx - cx| / halfW, |ny - cy| / halfH) <= reachNorm
  • Круг: ((nx - cx) / halfW)^2 + ((ny - cy) / halfH)^2 <= reachNorm^2
- Волновой алгоритм (Flood Fill) удаления фона с настраиваемой чувствительностью палочки (bgTolerance: 0..80).

[3.4] Оптическое распознавание текста с ROI-кроппингом (OcrEngine.kt):
- Перед передачей в ML Kit InputImage выполняется обрезка Bitmap по координатам ROI (Region of Interest),
  что снижает нагрузку на CPU в 10-15 раз и исключает ложные срабатывания от постороннего текста на экране.

 [3.5] В движок поиска (TemplateMatchingEngine), масок (SmartMaskEngine) и калибровки (CalibrationOverlay) внедрена строгая контурная верификация с правом вето:

Периметральная проверка силуэта (Silhouette Boundary Contrast):

4. ДВУХКОМПОНЕНТНЫЙ ВИРТУАЛЬНЫЙ ДЖОЙСТИК (Dual-Overlay Architecture)
--------------------------------------------------------------------------------
[4.1] Разделение оверлеев (JoystickOverlay.kt):
1. Оверлей Пульта управления (Control Pad):
   - Размещается в удобном месте для пальца (слева/справа).
   - Верхняя панель с ручкой DRAG_HANDLE для перемещения пульта по экрану.
   - 360° аналоговый стик Thumb Knob с ограничением хода knobRadiusLimit (46 dp).
   - Индикатор угла (0..360°) и мощности (0..100%).
   - Кнопка [⏺ ЗАПИСЬ / ⏹ СОХРАНИТЬ] и тумблер [LIVE: ON/OFF].
2. Оверлей Мишени в игре (Target Reticle):
   - Независимое окно, устанавливаемое игроком точно над зоной виртуального стика игры.
   - Свободно перемещается за любое место своего корпуса.
   - Внутри отображает активную точку (reticleCenterDot), синхронно повторяющую отклонение стика на пульте.

[4.2] Кинематическая трансляция в координаты игры:
- targetGameX = reticleCenterX + (normalizedMagnitude * reticleRadius * cos(angle))
- targetGameY = reticleCenterY + (normalizedMagnitude * reticleRadius * sin(angle))
- Инжекция происходит в координатах игры, полностью изолированно от пульта под пальцем.

5. СИМУЛЬТАННАЯ ЗАПИСЬ ЖЕСТОВ (GestureRecorderOverlay.kt)
--------------------------------------------------------------------------------
- При открытии режима записи касания пользователя перехватываются оверлеем.
- В реальном времени выполняется ДВОЙНОЕ действие:
  1. Точки (Point2D), траектория и тайминг записываются в буфер макроса.
  2. Одновременно вызывается dispatcher.dispatchSimultaneousTouch* для инжекции касания в игру.
- Игрок полноценно видит отклик персонажа и интерфейса игры прямо в процессе записи.
- При отпускании жест автоматически классифицируется:
  • < 30 px и < 400 мс -> CLICK
  • < 30 px и >= 400 мс -> LONG_PRESS
  • > 30 px и прямая линия -> SWIPE
  • > 40 px и сложная траектория (> 8 точек) -> PATH

6. AFK-ЗАЩИТА ЭКРАНА И PASSTHROUGH-МОСТ (ScreenLockOverlay.kt)
--------------------------------------------------------------------------------
- AMOLED-черный экран с минимальной яркостью (0.01) защищает от ложных нажатий в кармане.
- Разблокировка экрана: удержание пальца в течение 3 секунд со шкалой прогресса в верхнем HUD.
- Passthrough-мост:
  Когда макрос (MacroExecutionEngine) выполняет клики/свайпы, GestureDispatcher передает сигнал
  onGesturePassthroughToggle(true), временно активируя FLAG_NOT_TOUCHABLE на окне блокировки.
  Жест беспрепятственно проходит в игру. По завершении жеста блокировка сенсора мгновенно восстанавливается.

7. ИСПОЛНИТЕЛЬНЫЙ АВТОМАТ МАКРОСОВ (MacroExecutionEngine.kt)
--------------------------------------------------------------------------------
- Полнота FSM: исчерпывающая обработка 9 типов действий:
  1. CLICK: одиночное нажатие с рандомизацией радиуса (computeGaussianOffset).
  2. LONG_PRESS: длительное удержание.
  3. SWIPE: прямой векторный свайп по кривым Безье.
  4. PATH: криволинейная векторная траектория жеста.
  5. TRIGGER: поиск графического шаблона ИИ с переходами по условию (jumpToStepOnMatch / Timeout).
  6. OCR: поиск текста/регулярных выражений и условий {gold} >= 4000 (ExpressionEvaluator).
  7. COLOR_CHECK: валидация цвета пикселя с допуском tolerance.
  8. SUBROUTINE: переход в подпрограмму с сохранением индекса возврата (SubroutineManager, глубина до 50).
  9. RETURN: возврат из подпрограммы в точку вызова.
