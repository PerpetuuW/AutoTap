РАЗДЕЛ III. КОМПИЛЯТОРНАЯ И БАЙТКОДОВАЯ БЕЗОПАСНОСТЬ (JVM INTEGRITY)

[C-01] Защита от коллизий сигнатур JVM (Erasure Collision Shield)

1.  Запрещено объявлять перегрузки методов, типы параметров которых после
    стирания типов (Type Erasure) в байткоде JVM становятся эквивалентными.
2.  В Kotlin ссылки Type и Type? транслируются в идентичный дескриптор
    Ljava/lang/Type;. Запрещено объявлять методы, отличающиеся только признаком
    nullable ссылочного типа: создается ровно одна каноническая функция,
    принимающая nullable-параметр и инкапсулирующая безопасную проверку на null.

[C-02] Защита от дублирования внутренних структур данных (Unique Scoping)

1.  Вспомогательные кортежи (Quad, Tuple4, Holder) и вложенные структуры не
    могут объявляться повторно внутри одного класса во избежание коллизии
    байткода Duplicate JVM class name ...$Name.
2.  При необходимости использования кортежей объявляется единая каноническая
    обобщенная структура, снабженная сквозными свойствами-аксессорами для полной
    обратной совместимости.

[C-03] Защита от каскадного обвала вывода типов (Anti-Cascading Invariant)

1.  Категорически запрещено использовать вложенные цепочки функциональных
    функций области видимости (.let, .apply, .run) над выражениями, чей тип не
    гарантирован на этапе компиляции.
2.  Любая работа с потенциально отсутствующими элементами строится через плоские
    проверки на null:
    val target = findElementOrNull()
    if (target != null) {
        // Типобезопасная работа с гарантированным объектом
    }

[C-04] Строгая типизация контейнеров и примитивов

1.  Контейнеры динамического добавления View типизируются конкретными
    наследниками ViewGroup (FrameLayout?, LinearLayout?), исключая базовый
    View?.
2.  Числовые литералы обязаны строго соответствовать сигнатурам: целые числа
    (Int \rightarrow 0, Long \rightarrow 0L), числа с плавающей точкой (Float
    \rightarrow 0f, Double \rightarrow 0.0).
3.  Логические операции над Boolean? обязаны содержать явную редукцию к
    примитиву: val flag: Boolean = call() ?: false или сравнение call() == true.
4.  Табу на жесткое разыменование: Категорический запрет на оператор !! во всем
    коде. Разрешены только безопасные вызовы ?., элвис-операторы ?: или явный
    checkNotNull() с информативным сообщением.

[C-05] Совместимость с версиями платформы (Platform Capability Guard)

Методы и конструкторы, добавленные в более поздних версиях Android (например,
непрерывные жесты API 26+ continueStroke), обязаны сопровождаться:

1.  Аннотацией @RequiresApi(Build.VERSION_CODES.O) на уровне метода/класса.
2.  Предварительной рантайм-проверкой if (Build.VERSION.SDK_INT <
    Build.VERSION_CODES.O) return.

РАЗДЕЛ IV. РАНТАЙМ, СИНХРОНИЗАЦИЯ И КИНЕМАТИКА

[R-01] Задержка аппаратного композитинга (Display Buffer Flush Invariant)

1.  Асинхронность оконной подсистемы: Изменение видимости оверлеев (visibility =
    INVISIBLE или alpha = 0f) не очищает видеобуфер виртуального дисплея
    мгновенно в том же такте CPU.
2.  Two-Frame VSYNC Flush Barrier: Любой захват кадра экрана стороннего
    приложения через MediaProjection обязан выдерживать временной барьер не
    менее 2–3 аппаратных кадров композитора SurfaceFlinger
    (\approx 40–50\text{ мс}) после сокрытия оверлеев, гарантируя сброс
    конвейера тройной буферизации до считывания пикселей из ImageReader.
3.  Pre-Touch Snapshotting: Захват эталонных графических шаблонов производится
    строго до того, как физическое касание вызовет визуальное изменение целевого
    компонента (состояние нажатия, анимацию волны Ripple или смену цвета).

[R-02] Атомарность жизненного цикла жестов (Gesture Lifecycle Singularity)

1.  Одно физическое взаимодействие пользователя (ACTION_DOWN \rightarrow
    ACTION_UP) обязано приводить к созданию строго одной атомарной транзакции
    сценария.
2.  Запрещено дублировать регистрацию действий по разным фазам жеста (например,
    создание простого клика на DOWN и создание умного шага на UP).
3.  Любая регистрация действий на холсте записи защищается временным
    дебаунс-барьером (\ge 350–400\text{ мс}) для исключения повторного
    срабатывания от микро-дребезга сенсора или синтетических событий.
4.  Простая запись и Умная запись являются взаимоисключающими: простая запись
    оперирует исключительно числовыми координатами без вызова захвата экрана;
    умная запись формирует только шаблоны распознавания.

[R-03] Кинематика непрерывных жестов и субпиксельная стабильность

1.  Непрерывные жесты (джойстик, свайпы) передаются через синхронный протокол
    continueStroke() строго внутри коллбэка onCompleted() предыдущего отрезка.
2.  При статическом удержании координаты пути обязаны использовать субпиксельный
    микро-импульс (\Delta = \pm 0.5\text{ px}) для предотвращения аварийного
    сброса жеста системным инжектором AOSP (MotionEventInjector).

[R-04] Безопасность аппаратных буферов захвата (HardwareBuffer Lifecycle)

Любой захват кадра через MediaProjection / ImageReader обязан освобождать
нативные ресурсы строго в блоке finally:

val image = imageReader.acquireLatestImage() ?: return null
try {
    // Обработка битмапа / пикселей
} finally {
    image.hardwareBuffer?.close()
    image.close()
}

Пропуск закрытия буфера приводит к фатальному исчерпанию пула дескрипторов
графического драйвера и зависанию подсистемы захвата.

[R-05] Барьер исключения собственного UI из CV-поиска (Self-Match Exclusion Barrier)

Координаты и границы активных оверлеев приложения принудительно исключаются из
областей поиска шаблонов (isRegionExcluded == true). Запрещено регистрировать
координаты самого приложения в пул детекции.

РАЗДЕЛ V. ПРОТОКОЛ ПОСТАВКИ И САМОВОССТАНОВЛЕНИЯ

[D-01] Изоляция ресурсов и санитария рабочего дерева (AGP Quarantine)

1.  Запрещено создание резервных копий (.bak, .tmp, ~) внутри каталогов ресурсов
    res/. Любые бэкапы изолируются исключительно в скрытой директории
    .res_backup/ в корне проекта.
2.  Перед выполнением любых файловых операций запускается обязательная процедура
    санитарной очистки clean_illegal_res_backups().

[D-02] Защита строковых парсеров и синтаксис регуляризации

1.  Все регулярные выражения для работы с кодом компилируются строго в латинском
    Pure ASCII.
2.  Шестнадцатеричные экранирования Unicode в Python обязаны строго соблюдать
    стандарт разрядности: \uXXXX (ровно 4 символа) и \UXXXXXXXX (ровно 8
    символов). Запрещены неполные литералы.
3.  Нормализация окончаний строк: Все текстовые потоки считываются и
    записываются с явным указанием newline='\n' для исключения рассинхронизации
    символов возврата каретки (CRLF vs LF) на разных операционных системах.

[D-03] Валидация скобок и синтаксическая целостность (Bracket Guard)

1.  Перед фиксацией любых модификаций код файла проходит синтаксический анализ
    баланса парных скобок { }, ( ), [ ].
2.  Анализ игнорирует содержимое строковых литералов (одинарных, двойных и
    тройных кавычек), экранированных символов и однострочных/многострочных
    комментариев.
3.  При отрицательном балансе в любой точке или ненулевом балансе в конце файла
    запись блокируется, а файл откатывается.

[D-04] Изоляция поиска от блока импортов и балансный парсинг конструкторов

1.  Import Isolation: При поиске точек вызова или замене деклараций классов
    скрипт обязан явно игнорировать строки, начинающиеся с import .
2.  Balanced Constructor Scanner: Запрещено парсить параметры конструкторов
    нежадными квантификаторами .*?\). Парсинг вложенных выражений со значениями
    по умолчанию производится строго по балансному счетчику круглых скобок ( ).
3.  Single-Match Anchor Invariant: Блок строковой замены SEARCH обязан
    присутствовать в файле ровно один раз (code.count(search) == 1). Если число
    совпадений равно нулю или больше единицы, запись отменяется с выводом
    контекста в буфер обмена.

[D-05] Неблокирующий ввод-вывод и глобальный буфер обмена

1.  Все информационные сообщения выводятся с немедленным сбросом буфера вывода
    (flush=True).
2.  Любой сбой, синтаксическая ошибка или успешный отчет автоматически
    копируются в буфер обмена операционной системы (safe_copy_to_clipboard) с
    защитным таймаутом выполнения.

РАЗДЕЛ VI. УНИВЕРСАЛЬНЫЙ ПРЕФЛАЙТ И QA ЧЕК-ЛИСТ

Перед публикацией любого патча скрипт детерминированно верифицирует соблюдение
системных законов:

- [ ] 1. Zero-Unverified-Identifiers [A-01]: Все используемые символы и ID
  доказаны присутствием в макетах или кодовой базе; гипотезы и fallback-дефолты
  исключены.
- [ ] 2. Model SSOT [A-02]: Свойства доменных сущностей верифицированы по
  первичным конструкторам domain/model/*.
- [ ] 3. Resource Declarative Invariant [A-03]: Все прямые обращения R.id.*
  физически объявлены в XML-макетах проекта.
- [ ] 4. Official API Contract Compliance [A-04]: Все вызовы Android SDK,
  AndroidX и Kotlin строго верифицированы по официальной документации платформы
  (developer.android.com); сигнатуры, параметры, потоки и ограничения уровней
  API соблюдены.
- [ ] 5. Declarative Boundary [U-01]: Статический UI вынесен в XML-ресурсы и
  селекторы; процедурный код свободен от императивной верстки.
- [ ] 6. Touch Target Standard [U-02]: Интерактивные сенсорные элементы обладают
  зоной взаимодействия \ge 40–48\text{ dp} с поддержкой магнитного захвата.
- [ ] 7. Overflow Protection [U-02, U-04]: Горизонтальные панели тулбаров
  защищены от срезания границ экрана; узлы графа изолированы через clipPath и
  ellipsize.
- [ ] 8. Semantic Palette [U-03]: Цвета интерфейса строго сопоставлены
  функциональным статусам (Hero Purple, Danger Rose, Success Mint, Obsidian
  Surfaces).
- [ ] 9. Strict No-Emoji [U-03]: Все пиктограммы и управляющие символы
  формируются чистыми Canvas-векторами без шрифтовых эмодзи.
- [ ] 10. JVM Erasure Collision Guard [C-01]: Исключены перегрузки методов,
  совпадающие после стирания типов Type и Type?.
- [ ] 11. Unique Scoping [C-02]: Вспомогательные классы и структуры
  уникализированы во избежание коллизий байткода $Name.
- [ ] 12. Anti-Cascading Shield [C-03]: Исключены цепочки .let над
  непроверенными объектами; применен плоский null-check.
- [ ] 13. Bang-Bang Prohibition [C-04]: Полное отсутствие операторов жесткого
  разыменования !!.
- [ ] 14. API Capability Annotations [C-05]: Присутствуют аннотации @RequiresApi
  и рантайм-проверки версии ОС для вызовов API 26+.
- [ ] 15. Two-Frame VSYNC Barrier [R-01]: Захват экрана стороннего приложения

- [ ] 16. Pre-Touch Snapshotting [R-01]: Шаблон кнопки фиксируется до проявления
  анимации нажатия (Ripple) целевой системы.
- [ ] 17. Gesture Lifecycle Singularity [R-02]: Одно касание формирует ровно

- [ ] 19. HardwareBuffer Leak Guard [R-04]: Освобождение буферов Image и

- [ ] 20. Self-Match Exclusion [R-05]: Оверлеи приложения исключены из областей
